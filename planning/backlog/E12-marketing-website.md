- [ ] `E12-36` (risk:high) **The home page motion never ran in production, and the fix for it had made a heading unreadable.** Andy, on the live site: *"Nothing moves / transitions on the home page. 'Your school gets its own menu' has bad contrast with background and can't be read."* Two unrelated causes, both found by probing the deployed site rather than the local build. **(1)** `netlify.toml` sends `script-src 'self'` and `E12-35`'s script was `is:inline`, so the browser refused it — `html.js` was never added, nothing was ever hidden, and nothing ever animated. It worked locally because a static file server sends no CSP. The code moved to `src/lib/site/motion.ts` and is now imported by a bundled `<script>`, served from the origin. `check-build.mjs` fails the build on any inline `<script>` without `src` (JSON-LD excepted), so this cannot come back — and that guard was itself first written *after* the `process.exit(1)` that ends the report, where it could never fire; it was proven by injecting a script into `dist/` and watching it fail. **(2)** The reveal rule was `[data-reveal] > *`, specificity (0,1,1), which beat `.pattern--deep`'s `opacity: 0.11` at (0,1,0) and painted the decorative vegetable pattern at **nine times** its intended strength directly behind that heading. Scoped to `> .wrap`, so it can only ever touch the content column. Also: the failsafe went from three seconds to ten, because at three it fired before a reader had scrolled and revealed every section — the safety net was switching the feature off on every normal visit.
