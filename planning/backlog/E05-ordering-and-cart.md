- [ ] `E05-52` **`order-calendar` cannot work for the audience it is for.** `resolve_effective_config` and `orderable_calendar` are both SECURITY INVOKER, and the config tables they read (`platform_config`, `kitchen_config`, `school_config`) are readable only by an admin holding `config.platform_edit` / `kitchen.config_edit` / `school.config_edit`. So the endpoint returns `404 no configuration for that school` for every parent, including one with a child at that school. Verified on production. **Not launch-blocking**: no mobile screen calls it yet — only `packages/shared/src/ordering/calendar-endpoint.ts` and the function shell exist, so this is an endpoint built ahead of its consumer. It must be fixed before anything calls it, and the fix is a decision rather than a typo: make the resolver SECURITY DEFINER (config is not secret, but it is not obviously public either), or expose a narrow read of just the ordering-relevant fields.
